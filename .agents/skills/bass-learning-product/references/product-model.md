# Bass Practice Studio 产品模型

## 产品定位

Bass Practice Studio 是帮助初中级贝斯学习者把“我不知道该练什么”转化为可执行训练的浏览器学习系统。它不是贝斯资料下载站，也不以曲谱数量作为核心价值。

核心闭环固定为：

`诊断能力 → 找到短板 → 获得练习 → 完成验收 → 更新能力地图`

## 目标用户与场景

- 目标用户：掌握基础演奏、但缺少系统训练路径的初中级学习者。
- 典型场景：用户只有一段有限练习时间，希望快速知道今天练什么、为什么练、怎样算完成。
- 核心价值：减少选择成本，让一次练习有明确目标、标准和后续反馈。

## 六维能力模型

| 维度 | 初学者解释 | 可观察表现 |
| --- | --- | --- |
| 指板 | 知道音在琴颈哪里 | 能找到目标音并在把位间移动 |
| 和声 | 知道音为什么适合当前和弦 | 能使用根音、和弦音和经过音 |
| 节奏 | 在时间线上稳定地放置音符 | 能跟拍、处理八分音符与切分 |
| 技术 | 用合适动作清楚省力地发音 | 能控制左右手、闷音和音色一致性 |
| 表达 | 让演奏具有力度、律动和句子感 | 能控制重音、动态和 articulation |
| 迁移 | 把学会的方法用于新音乐 | 能在新调、新和弦或新歌曲中复用能力 |

不要仅因用户点击完成就提高能力值。能力更新应对应可说明的练习证据或验收规则；没有可靠证据时，只记录练习行为。

## 页面原则

1. 每个页面都推动用户完成下一步练习。
2. 一个页面只保留一个主要操作；次要操作降低视觉权重。
3. 首屏或练习选择点回答四件事：
   - 我现在处于什么水平或哪项能力较弱；
   - 我今天应该练什么；
   - 为什么推荐这个练习；
   - 完成或通过的标准是什么。
4. 不用大量统计数字制造虚假的专业感。
5. 不确定、未接通或仅在本地可用的功能不得伪装成线上可用。
6. 静态数据、模拟数据和真实数据必须明确区分。
7. 专业术语首次出现时提供初学者能理解的解释。
8. UI 像安静、专业的音乐练习室：层级清楚、留白充足、颜色克制、注意力集中。
9. 优先保证手机、平板和电脑上的可读性与主要操作可达性。

## 推荐与验收规则

- 推荐至少包含：目标能力、推荐原因、练习时长或次数、通过标准。
- 推荐原因必须能追溯到诊断结果、历史记录或用户主动选择；否则标成通用推荐。
- 固定条件、打分表或 if/else 逻辑称为“规则推荐”，不得称为 AI。
- “完成练习”只代表行为记录；“通过验收”需要满足明确标准。
- 无法自动判断音准、节奏或动作质量时，说明采用自评、人工确认或尚未接通，不能假装系统已听懂演奏。

## 状态完整性

- 空状态：说明为什么没有内容，并给出唯一的下一步。
- 加载状态：说明系统正在做什么，避免重复提交。
- 成功状态：准确说明保存、完成或通过中的哪一种结果。
- 失败状态：说明失败环节、可能原因和恢复方法。
- 离线或本地存储：说明数据保存位置及清除浏览器数据后的影响。

## 修改与验证边界

- 修改前先分析实际代码和用户流程，提供方案并等待确认。
- 不因页面存在就判断功能已接通；验证事件处理、数据来源和结果保存。
- 验证桌面、平板、手机布局，键盘操作，以及空、加载、成功、失败状态。
- 未经明确请求，不部署、不上传、不写入外部服务、不产生付费调用。
